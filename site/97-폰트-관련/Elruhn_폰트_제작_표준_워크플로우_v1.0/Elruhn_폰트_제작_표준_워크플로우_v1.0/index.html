          Elruhn 폰트 제작 표준 워크플로우 v1.0

          목표: Calligraphr에 의존하지 않고, Adobe Illustrator를 중심으로 Elruhn Text(디지털 정자체)와 Elruhn Script(연결 필기체)를 독립적인 고품질 폰트 패밀리로 구축한다. Photoshop과 실제 종이 필기 샘플은 보조 자료로 사용하며, 최종 글리프의 정본은 벡터 마스터로 관리한다.

          0. 핵심 결론

          최선의 제작 방식은 다음과 같다.

          Illustrator = 글리프 정본(master)
          Photoshop = 러프 스케치·스캔 정리·비교 시트
          종이 필기 = 필기 동작과 연결 규칙을 추출하는 참고자료
          최종 폰트화 = 벡터 글리프 + 폰트 메트릭 + OpenType 규칙을 결합하여 TTF/OTF/WOFF2로 빌드

          따라서 종이에 그린 글자를 그대로 스캔하여 폰트로 쓰지 않는다. 종이 샘플은 Elruhn Script의 연결 방식, 획 생략, 속도에 따른 변형, 시작·종결 형태를 분석하기 위한 자료다. Elruhn Text와 Elruhn Script의 최종 자형은 Illustrator의 벡터 패스로 관리한다.

          1. 최종 폰트 패밀리 구조

          1.1 Elruhn Text

          용도: 디지털 본문, 설정집, 웹, 지도 라벨, 행정문서, UI, 표지·간판의 기본 활자.

          설계 원칙:

          • 직립에 가까운 안정된 축
          • 획 굵기·곡률·끝처리 규격화
          • 글자별 폭과 내부 공간(counter)의 가독성 우선
          • 작은 크기에서도 서로 다른 글자가 명확히 구분되도록 설계
          • 연결 획을 사용하지 않음
          • 장식은 식별성을 해치지 않는 범위에서 제한

          1.2 Elruhn Script

          용도: 실제 필기, 서신, 서명, 일지, 문학적 인용, 개인 기록, 의례·장식용 문구.

          설계 원칙:

          • 같은 Elruhn 글자라는 골격은 Text와 공유
          • 자연스러운 손글씨 곡률과 약간의 비대칭 유지
          • 입필(entry)·출필(exit) 방향을 설계 단계부터 관리
          • 문맥에 따라 시작형·중간형·종결형·비연결형·대체형을 사용
          • 자주 등장하는 조합은 합자(ligature)를 허용
          • 같은 글자가 반복될 때 기계적인 복제감이 줄어들도록 대체 글리프를 사용

          1.3 명칭

          기존 Gara 표기는 폰트 패밀리명에서 제거한다.

          권장 이름:

          • Family: Elruhn Text
          • Style: Regular
          • PostScript name: ElruhnText-Regular
          • Family: Elruhn Script
          • Style: Regular
          • PostScript name: ElruhnScript-Regular

          향후 확장 예시:

          • Elruhn Text Medium / Bold
          • Elruhn Script Formal / Natural

          2. 도구별 역할 분담

          도구주 역할하지 않는 것
          Adobe Illustrator최종 글리프 벡터 마스터, 기준선·곡선·획 규격 관리스캔 노이즈가 남은 상태를 정본으로 사용하지 않음
          Adobe Photoshop러프, 손그림, 스캔 보정, 레퍼런스 비교 시트최종 정본 글리프를 래스터 레이어만으로 관리하지 않음
          종이 + 펜실제 필기 습관, 연결, 속도별 변형 채집스캔 이미지를 그대로 최종 글리프로 쓰지 않음
          폰트 빌드 단계Unicode/키 매핑, 메트릭, 커닝, OpenType 기능, TTF/OTF/WOFF2 생성자형 디자인의 원본을 별도로 재해석하지 않음

          원칙: Illustrator 파일과 개별 SVG가 장기 보존할 정본이며, TTF/OTF/WOFF2는 언제든 재생성 가능한 배포 산출물로 취급한다.

          3. Illustrator 마스터 파일 설계

          3.1 아트보드 크기

          권장: 글리프 1개당 3000 × 3000 px 아트보드.

          Illustrator는 벡터 기반이므로 실제 품질은 픽셀 수에 종속되지 않는다. 3000 × 3000은 다음 이유로 작업 좌표를 직관적으로 유지하기 위한 규격이다.

          • 펜/연필 도구로 세밀한 수정이 편함
          • Photoshop 러프나 스캔 샘플을 같은 크기로 배치하기 쉬움
          • PNG 비교본을 고해상도로 뽑기 쉬움

          한 파일 안에 A-Z / a-z용 아트보드를 순서대로 두되, 아트보드 이름을 반드시 키와 동일하게 지정한다.

          예: a, b, c … z, A, B … Z

          3.2 공통 가이드

          3000 × 3000 기준 권장 시작값:

          기준선Y 위치(상단 기준)역할
          Top / Ascender limit450위쪽 장식·상승부의 최대 안전선
          Main top800일반 본체의 상단 기준
          Mid / optical guide1500대칭·중심 판단용
          Baseline2250대부분의 글리프가 착지하는 기준선
          Descender limit2700하강부의 최대 안전선

          이 좌표는 절대 규칙이 아니라 첫 마스터를 만들기 위한 공통 작업 격자다. 대표 글리프를 설계한 후 실제 Elruhn의 비례가 더 좋아 보이면 전체 가이드를 한 번에 조정한다.

          추가 가이드:

          • 세로 중앙선 X=1500
          • 좌우 안전영역 X=350 / 2650
          • 곡선 오버슈트 허용선: Main top과 Baseline에서 약 1.5~2.5% 범위

          주의: 곡선 글리프가 수학적으로 기준선에 정확히 닿아 있으면 시각적으로 작아 보일 수 있다. 원형·아치형 글자는 optical overshoot를 허용한다.

          3.3 레이어 구조

          각 아트보드는 다음 레이어 구조를 공유한다.

          00_Guides_LOCKED
01_Reference
02_Skeleton
03_Editable_Stroke
04_Final_Outline
05_Connection_Marks   (Script 전용)
06_Notes
          • 00_Guides_LOCKED: 기준선, 안전영역. 항상 잠금.
          • 01_Reference: 기존 Elruhn PNG, 이전 폰트 렌더, 종이 필기 참고 이미지.
          • 02_Skeleton: 글자의 뼈대와 중심 흐름.
          • 03_Editable_Stroke: Width Tool, 브러시, 스트로크 기반 편집본. 수정용 정본.
          • 04_Final_Outline: Expand 후의 닫힌 벡터 윤곽. 폰트 빌드용.
          • 05_Connection_Marks: Script의 입필/출필 위치·각도 표시.
          • 06_Notes: 예외 규칙, 다른 글자와의 관계, 수정 메모.

          절대 원칙: Editable_Stroke를 유지하고 Final_Outline만 남기지 않는다. 그래야 획 굵기나 곡률을 나중에 다시 조정할 수 있다.

          4. 벡터 제작 방식

          4.1 정자체(Text)

          권장 순서:

          1. Skeleton으로 글자의 핵심 구조를 잡는다.
          2. 선형 획은 가능한 한 공통 두께 규칙을 적용한다.
          3. 곡선은 최소한의 Bézier 포인트로 구성한다.
          4. 대칭이 필요한 부분은 수학적 대칭을 출발점으로 하되, 최종적으로 optical correction을 적용한다.
          5. 교차부와 루프 내부가 작은 크기에서 뭉치지 않는지 확인한다.
          6. 최종 단계에서 Outline으로 확장한다.

          권장 규칙:

          • 한 곡선 구간에 불필요한 앵커를 만들지 않는다.
          • 수평·수직 극점(extrema)에 앵커를 두는 것을 기본으로 한다.
          • 작은 돌출부·미세한 흔들림은 삭제한다.
          • 서로 비슷한 글자는 내부 공간이나 종결부를 의도적으로 다르게 하여 식별성을 확보한다.

          4.2 필기체(Script)

          Script는 글자 모양보다 ‘획의 흐름’이 먼저다.

          권장 순서:

          1. Skeleton에서 실제 한 번의 펜 동작처럼 흐름을 설계한다.
          2. 입필점과 출필점을 표시한다.
          3. 연결 가능한 글자끼리는 기준 접속 높이와 각도를 맞춘다.
          4. 연결 때문에 기본 자형이 무너지면 문맥형 대체 글리프를 만든다.
          5. Width Tool 또는 압력형 브러시로 획 굵기를 조정한다.
          6. Outline으로 확장하되, 원본 스트로크는 보존한다.

          연결점은 최소 다음 정보를 기록한다.

          • entry Y
          • entry angle
          • exit Y
          • exit angle
          • 연결 가능/불가 여부
          • 위쪽 연결/아래쪽 연결 등 특수 유형

          5. 대표 글리프 우선 설계

          처음부터 52자를 모두 완성하지 않는다.

          먼저 구조적으로 어려운 8~12개 대표 글리프를 Text와 Script 양쪽에서 확정한다. 현재 Elruhn에서는 다음 키를 우선 샘플로 삼는 것이 좋다.

          E/e, G/g, K/k, P/p, Q/q, T/t, Y/y

          필요하면 다음을 추가한다.

          A/a, M/m, R/r, S/s

          대표 세트가 다루어야 하는 요소:

          • 직선 중심형
          • 큰 곡선/루프형
          • 교차형
          • 하강형
          • 비대칭형
          • 점·장식형
          • 연결이 쉬운 글자
          • 연결이 어려운 글자

          대표 글리프에서 다음 규칙을 먼저 결정한 뒤 나머지 문자에 전파한다.

          • 기본 획 두께
          • 세로/가로 획 비율
          • 곡선 반경의 성격
          • 모서리 처리
          • 갈고리 길이
          • 루프 크기
          • 장식점 크기와 위치
          • 기울기
          • Text와 Script 사이에 반드시 유지할 공통 골격

          6. Elruhn Text 제작 규격

          6.1 목표

          “필기체를 반듯하게 세운 폰트”가 아니라 Elruhn의 공식 디지털·인쇄 표준자형을 만든다.

          6.2 핵심 규칙

          • 전체 글자의 시각적 무게를 맞춘다.
          • 너무 가는 내부 공간은 넓힌다.
          • 긴 획의 기울기는 문자군별로 통일한다.
          • 장식 요소는 동일 계열끼리 크기와 배치 규칙을 공유한다.
          • 같은 구조를 가진 부분은 재사용 가능한 Illustrator component처럼 관리한다.
          • 모든 글자를 같은 폭으로 강제하지 않는다. 실제 글자 형태에 맞는 proportional width를 사용한다.
          • 다만 좌우 side bearing은 유형별로 일정한 계열을 갖게 한다.

          6.3 크기별 검수

          반드시 다음 크기에서 테스트한다.

          • 12 px: 본문 최소 수준
          • 16 px: 일반 웹 본문
          • 24 px: UI/강조
          • 48 px 이상: 제목/라벨

          12~16 px에서 내부 공간이 막히거나 두 글자가 구별되지 않으면 원본 디자인을 조금 단순화하는 편이 맞다.

          7. Elruhn Script 연결 필기체 구현

          7.1 기본 개념

          연결 필기체는 모든 글자를 단순히 좌우로 붙이는 방식으로 만들지 않는다. 글자마다 문맥형 글리프를 준비하고 OpenType 치환 규칙을 사용한다.

          권장 글리프 계층:

          • 기본형(base)
          • 시작형(initial)
          • 중간 연결형(medial/connect)
          • 종결형(final)
          • 비연결형(non-joining)
          • 대체형(alt01, alt02 …)
          • 합자(ligature)

          7.2 OpenType 기능

          중심 기능:

          • calt — contextual alternates. 앞뒤 글자에 따라 연결형을 자동 선택하는 핵심 기능.
          • liga — 일반 합자. 자주 등장하는 2~3자 조합을 하나의 자연스러운 연결 형태로 치환.
          • rlig — 반드시 필요한 연결 합자가 생길 경우 제한적으로 사용.
          • salt / ss01 등 — 사용자가 선택할 수 있는 스타일 대체형을 제공할 때 사용.
          • kern / GPOS — 연결되지 않는 조합의 간격 보정.

          중요한 구현 원칙

          현재 개발 편의를 위해 Elruhn을 Latin A-Z/a-z에 매핑하므로, init/medi/fina에만 의존하는 방식은 앱별 처리 차이가 생길 수 있다. 기본 연결은 calt의 문맥 치환을 중심으로 설계하는 것이 안전하다.

          호환성을 위해:

          1. 기본 Script 글리프만 사용해도 완전히 깨져 보이지 않아야 한다.
          2. calt가 활성화된 앱에서는 시작/중간/종결 형태가 자연스럽게 바뀌도록 한다.
          3. 특정 앱에서 OpenType 기능이 꺼져도 최소한 단어 형태는 읽을 수 있도록 한다.

          7.3 실제 연결 데이터 채집

          모든 가능한 26×26 조합을 직접 디자인할 필요는 없다.

          먼저 글자를 연결 유형으로 분류한다.

          예:

          • L: 낮은 위치에서 나가는 글자
          • H: 높은 위치에서 나가는 글자
          • D: 아래로 내려간 뒤 올라오는 글자
          • N: 연결하지 않는 글자

          그다음 L→L, L→H, H→L 등의 유형 규칙을 만든다. 예외 조합만 별도의 대체 글리프나 합자로 처리한다.

          8. 종이 필기 샘플의 올바른 사용법

          8.1 왜 종이 샘플을 쓰는가

          종이 필기는 최종 윤곽을 얻기 위한 것이 아니라 다음을 알아내기 위한 것이다.

          • 사람이 실제로 어느 방향으로 획을 이어가는지
          • 앞뒤 글자에 따라 어느 획이 자연스럽게 줄어드는지
          • 빠르게 쓸 때 무엇이 생략되는지
          • 반복해서 쓸 때 변하지 않는 핵심 골격이 무엇인지
          • 한 글자가 어느 정도까지 변형되어도 같은 글자로 인식되는지

          8.2 권장 채집 방식

          정자체(Text)는 종이 샘플이 필요 없다.

          Script가 어느 정도 디지털로 확정된 뒤 다음 세 종류를 작성한다.

          1. 정갈하게 천천히 쓴 필기
          2. 평소 속도의 자연스러운 필기
          3. 의도적으로 빠르게 쓴 필기

          각 문자는 단독으로 510회 정도, 핵심 글자는 1020회 정도 쓰면 충분하다.

          그다음 연결 조합을 작성한다.

          • 자주 쓰는 음절/철자 조합
          • 연결이 어려운 조합
          • 실제 Elruhn 단어와 문장

          8.3 스캔 권장값

          • 평판 스캐너 사용 시: 600 dpi 권장
          • 모드: Grayscale 또는 24-bit Color
          • 저장: PNG 또는 무손실 TIFF
          • JPEG는 가능하면 피함
          • 자동 샤프닝/노이즈 제거/문서 보정 기능은 최소화
          • 종이가 구겨지거나 원근이 생기지 않게 평평하게 스캔

          600 dpi 스캔은 최종 글리프로 그대로 사용하기 위한 품질이 아니라, 획 방향과 곡률·연결 습관을 판독하기에는 충분한 품질이다.

          8.4 Photoshop에서 하는 일

          스캔본은 Photoshop에서 다음만 처리한다.

          • 수평 보정
          • Levels/Curves로 대비 정리
          • 배경 종이색 제거 또는 약화
          • 개별 샘플 분리
          • 같은 글자의 여러 필기를 한 장에 비교 배치

          그 뒤 Illustrator Reference 레이어에 넣고 벡터 자형을 다시 설계한다.

          9. Photoshop을 이용한 디지털 러프

          종이 대신 액타로 자유롭게 그리고 싶다면 Photoshop을 사용할 수 있다.

          권장 방식:

          • 3000 × 3000 px 또는 그 이상
          • 투명 배경
          • 1글자 1레이어 또는 1글자 1파일
          • 가이드 레이어는 별도 잠금
          • 가능하면 단색 검정 브러시 사용
          • 브러시 안정화는 과도하게 높이지 않음

          Photoshop 러프 역시 최종 정본이 아니다. Illustrator에서 베지어 곡선으로 재구성하는 참고 자료로 사용한다.

          예외: Photoshop의 Shape/Pen 레이어로 처음부터 벡터로 만든 경우에는 Illustrator로 옮겨 최종 마스터로 승격할 수 있다.

          10. Illustrator → 폰트 빌드용 SVG 인계 규격

          각 글리프의 Final_Outline을 SVG로 별도 내보낸다.

          파일명:

          a.svg
b.svg
...
z.svg
A.svg
B.svg
...
Z.svg

          SVG 요구사항:

          • 문자 외곽은 닫힌 filled path
          • stroke만 존재하는 오브젝트 없음
          • 클리핑 마스크 없음
          • 이미지 링크 없음
          • 불필요한 그룹/필터/효과 제거
          • self-intersection 최소화
          • compound path의 내부/외부 방향 일관성 유지
          • 아트보드 좌표와 기준선이 모든 파일에서 동일

          함께 전달할 파일:

          • Elruhn_Text_Master.ai
          • Elruhn_Script_Master.ai
          • Text/SVG/*.svg
          • Script/SVG/*.svg
          • Script의 연결 규칙 메모
          • 실제 필기 스캔 참고본

          11. 키 매핑과 Unicode 전략

          초기·중기 제작에서는 현재처럼 a-z / A-Z 매핑을 유지하는 것이 가장 편하다. 기존 Elruhn 문장 데이터를 그대로 테스트할 수 있기 때문이다.

          추후 필요하면 다음 방식으로 확장할 수 있다.

          • 기존 Latin 키 매핑 유지
          • 동시에 Private Use Area(PUA)에 Elruhn 전용 코드포인트를 추가

          그러나 PUA 체계를 먼저 만들 필요는 없다. 먼저 자형과 입력 규칙을 안정화한 뒤 결정한다.

          12. 폰트 메트릭 설계

          Illustrator의 3000 px 좌표를 폰트 내부 UPM으로 정규화한다.

          권장 빌드 기준:

          • UPM: 1000 또는 2048
          • Text와 Script는 가능하면 같은 UPM 사용
          • ascender/descender는 실제 글리프 최대 범위를 기준으로 여유 있게 설정
          • Windows와 웹에서 하강부가 잘리지 않도록 OS/2, hhea 메트릭을 함께 검수

          각 글리프마다 관리할 항목:

          • advance width
          • left side bearing
          • right side bearing
          • bounding box
          • baseline relation
          • optical overshoot

          Script는 연결점 때문에 무조건 side bearing을 0으로 만드는 방식은 피한다. OpenType 조정과 실제 연결 구조를 함께 고려한다.

          13. 커닝과 Script 연결 규칙

          Text

          먼저 글자를 형태별 그룹으로 나눈다.

          • 평평한 좌변
          • 둥근 좌변
          • 돌출 좌변
          • 평평한 우변
          • 둥근 우변
          • 돌출 우변

          클래스 커닝을 기본으로 하고, 이상한 조합만 예외 커닝을 둔다.

          Script

          우선순위:

          1. 기본 entry/exit 위치를 맞추어 별도 커닝 없이도 연결되게 함
          2. calt로 문맥형 글리프 선택
          3. 예외적 연결에 GPOS 조정
          4. 자주 등장하면서 독립 디자인 가치가 있는 조합에만 liga

          모든 글자쌍을 합자로 만드는 것은 금지한다. 관리가 불가능해지고 자연스러움도 오히려 떨어진다.

          15. 단계별 실제 작업 순서

          Phase 0 — 기존 자료 보존

          • 현재 TTF/OTF/WOFF2, Calligraphr 템플릿, PSD/PNG를 Archive로 복사
          • 기존 파일은 수정하지 않음

          Phase 1 — 공통 문자 골격 확정

          • 기존 Elruhn에서 모든 글자의 핵심 식별 특징을 추출
          • Text/Script 공통으로 반드시 유지할 구조를 기록

          Phase 2 — 대표 글리프 제작

          • Text 8~12자
          • Script 동일 8~12자
          • 두 패밀리가 같은 문자로 보이면서도 성격은 확실히 다른지 비교

          Phase 3 — 디자인 규칙 고정

          • 획 굵기
          • 곡률
          • 장식
          • 기울기
          • 루프
          • baseline/overshoot
          • Script entry/exit 규칙

          Phase 4 — 전체 Text 제작

          • 52자 확장
          • side bearing 조정
          • 커닝
          • 12~48 px 가독성 검수

          Phase 5 — Script 기본형 제작

          • 52자 기본형
          • 입필/출필 분류
          • 연결 유형 그룹화

          Phase 6 — 실제 필기 자료 채집

          • 형이 실제 종이에 여러 속도로 Elruhn을 필기
          • 600 dpi 스캔
          • 자연스러운 연결과 변형 규칙 분석

          Phase 7 — Script 문맥형 확장

          • 시작형/중간형/종결형
          • 대체형
          • 필요한 합자
          • calt/liga 규칙

          Phase 8 — 폰트 빌드

          • TTF
          • OTF
          • WOFF2
          • 이름/메트릭/OpenType 테이블 정리

          Phase 9 — 실제 환경 테스트

          • Windows 폰트 렌더링
          • Word 또는 일반 문서 앱
          • Chromium 기반 브라우저
          • Obsidian
          • Obsidian Publish/웹 CSS

          Phase 10 — 릴리스

          • Text와 Script 각각 버전 부여
          • AI/SVG 마스터와 release font를 분리 보존

          16. 형이 준비해서 넘겨주면 되는 자료

          첫 번째 인계 — 디자인 방향 확정용

          1. Elruhn_Text_Master.ai 또는 대표 글리프 SVG
          2. Elruhn_Script_Master.ai 또는 대표 글리프 SVG
          3. Text/Script 각각 대표 글리프 8~12개
          4. “반드시 유지할 특징”이 있다면 Notes 레이어에 표기

          이 단계에서는 종이 스캔이 필요 없다.

          두 번째 인계 — Script 연결 고도화용

          18. 품질 검수 체크리스트

          공통

          • 모든 글리프가 baseline 규칙을 따른다.
          • 의도하지 않은 좌우 기울기 차이가 없다.
          • Bézier 앵커가 과도하게 많지 않다.
          • self-intersection, 열린 path, stray point가 없다.
          • 내부 구멍(counter)이 올바르게 뚫려 있다.
          • 대문자/소문자 매핑이 기존 입력 규칙과 일치한다.
          • ascender/descender가 앱에서 잘리지 않는다.

          Text

          • 12 px에서도 식별 가능하다.
          • 비슷한 글자가 서로 충분히 구분된다.
          • 획 굵기와 장식 크기의 체계가 일관된다.
          • 글자 폭이 지나치게 들쭉날쭉하지 않다.
          • 긴 문장에서 리듬이 안정적이다.

          Script

          • 연결선이 글자 사이에서 갑자기 꺾이지 않는다.
          • 연결점 높이가 문맥에 따라 자연스럽다.
          • 첫 글자와 마지막 글자가 억지로 연결되지 않는다.
          • 연결 불가 글자 처리 규칙이 있다.
          • 같은 글자가 반복될 때 지나치게 기계적으로 보이지 않는다.
          • calt 비활성 환경에서도 읽을 수 있다.
          • 합자를 과도하게 사용하지 않는다.

          배포

          • TTF/OTF/WOFF2가 같은 자형과 매핑을 갖는다.
          • family/style/PostScript 이름 충돌이 없다.
          • 기존 구버전 폰트와 별도 설치 테스트를 한다.
          • 웹에서 CORS/경로 문제 없이 WOFF2가 로드된다.
          • Obsidian과 Publish에서 실제 Elruhn 문장 테스트를 한다.

          19. 권장 결정: 지금부터 무엇을 할 것인가

          현재 단계에서는 새 폰트를 52자 전체부터 다시 그리지 않는다.

          가장 효율적인 다음 작업은 다음과 같다.

          1. Illustrator에 3000 × 3000 공통 마스터 템플릿을 만든다.
          2. 기존 Elruhn 원형을 Reference 레이어에 배치한다.
          3. Text 대표 글리프 8~12개를 새로 설계한다.
          4. 같은 글자를 Script 버전으로 설계한다.
          5. 두 스타일의 조형 규칙이 만족스러운지 먼저 확정한다.
          6. 그 뒤에만 52자 전체로 확장한다.
          7. Script 기본형이 완성된 후 실제 종이 필기 샘플을 채집한다.
          8. 종이 샘플에서 얻은 연결 규칙을 calt·합자·대체 글리프에 반영한다.

          이 방식이 재작업을 가장 줄이면서도, Elruhn을 단순 커스텀 폰트가 아니라 정자체와 실제 필기체를 갖춘 독립 문자 서체 체계로 발전시키는 가장 안정적인 경로다.
